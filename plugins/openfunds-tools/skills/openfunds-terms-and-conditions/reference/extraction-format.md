# Intermediate extraction format

The model produces one JSON object. The writer expands it into transmission rows only after validation.

```json

  "metadata": {
    "fund_name": "Umbrella - Sub-Fund legal name",

    "skill_version": "2.0.0",
    "status": "draft",
    "document_scope": "binding",
    "scope_evidence": "Prospectus title and operative wording, page 1."
  },
  "open_questions": [],
  "share_classes": [
    {
      "class_id": "SC-R-USD",
      "extension": "R-USD",
      "isin": null,
      "currency": "USD",
      "open_questions": ["Can you supply the ISIN for R-USD?"]
    }
  ],
  "candidates": [
    {
      "candidate_id": "C-ABC123",
```

## Fields generated by code

Do not put these in `rules[].fields`:

- OFST010020 comes from `metadata.fund_name`.
- OFST020050 and OFST020000 come from `share_classes`.
- OFTC005005 is generated from the source hash and `group_sources`.
- OFTC005050 is assembled from evidence quotes.

## Candidate rules

Copy candidates from the discovery output and complete their disposition. Do not delete inconvenient or irrelevant candidates. Rejected candidates are evidence of coverage.

`reason` is mandatory for every disposition except `mapped`. A mapped candidate must name every rule row it supports in `rule_ids`.

## Rule rows and grouping

One item in `rules` is one distinct output rule row before class expansion. A three-tier fee therefore has three rule items. Give all three the same `group_sources` so they receive the same OFTC005005 key.

`applies_to` contains class IDs, not class names or ISINs. The writer performs the repetition.

## Evidence

Quotes must be verbatim, contiguous and present at the stated location in `staged.md`. Use separate evidence items for separate passages.

Every populated OFTC field except the model-written short description must appear in at least one evidence item's `supports` list. A derived offset is still supported by the source wording that states the period; explain the conversion in `notes`.

## Questions and notes

- Fund questions belong in top-level `open_questions`.
- Missing class identifiers belong on the share-class object.
- Ambiguous rule interpretation belongs on the rule.
- Notes explain a reading or conversion but do not ask for a decision.
